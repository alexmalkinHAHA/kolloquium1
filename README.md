# Отработка коллоквиума 1 — сайт для студентов

Сайт даёт студенту 6 случайных задач того типа, который он решил плохо
на коллоквиуме (6 задач — если не решил вообще, 3 — если решил
наполовину), проверяет числовой ответ автоматически и даёт загрузить
фото решения. Вы как преподаватель видите все результаты и фото в
закрытой админ-панели.

В папке уже лежит **банк из 180 задач** (`bank.json`, 30 на каждый из
6 типов коллоквиума) — все числа подобраны программой так, чтобы быть
целыми и «красивыми» (без округлений).

Сайт полностью статический (HTML/CSS/JS) — его можно разместить на
GitHub Pages бесплатно. Для хранения результатов и фото используются
два бесплатных облачных сервиса: **Firebase** (таблица результатов,
без привязки карты) и **Cloudinary** (хранение фото, без привязки
карты). Всё это нужно один раз настроить — дальше сайт работает сам.

---

## 0. Проверка «на месте» перед настройкой (необязательно)

Если просто открыть `index.html` двойным кликом, сайт запустится в
**демо-режиме**: все данные сохраняются только в вашем браузере
(localStorage), никуда не отправляются. Так можно сразу посмотреть,
как всё работает, не создавая ничего. Пароль администратора в
демо-режиме: `demo`. Как только впишете реальные ключи в `config.js`
(шаги ниже) — демо-режим выключится сам.

Для демо-режима откройте файл через локальный сервер (иначе браузер
заблокирует загрузку `bank.json` с диска), например:

```
cd site
python3 -m http.server 8080
```

и зайдите на `http://localhost:8080`.

## 1. Firebase — таблица результатов (бесплатно, без карты)

1. Зайдите на **console.firebase.google.com**, войдите с Google-аккаунтом,
   нажмите **«Добавить проект»**, дайте любое имя (например
   `kolloquium1`), отключите Google Analytics (не нужна), создайте проект.
2. В меню слева откройте **Build → Firestore Database → Создать базу
   данных**. Выберите любой регион, режим — **«Начать в тестовом
   режиме»** (правила мы заменим на свои на шаге 3).
3. В меню слева откройте **Build → Authentication → Начать работу**.
   На вкладке **Sign-in method** включите провайдер **Email/Password**.
   Затем на вкладке **Users** нажмите **«Добавить пользователя»** и
   создайте себя как преподавателя: укажите свой email и пароль — это
   и будет вход в админ-панель сайта.
4. Откройте **Project settings** (шестерёнка слева вверху) → вкладка
   **General** → внизу раздел **«Ваши приложения»** → нажмите иконку
   **`</>`** (веб-приложение), дайте имя, **Firebase Hosting не
   подключайте**. После создания вам покажут объект `firebaseConfig` —
   скопируйте его целиком, он понадобится на шаге 4.
5. Вернитесь в **Firestore Database → вкладка Rules**, вставьте туда
   содержимое файла `firestore.rules` из этой папки **вместо
   `teacher@example.com` впишите свой реальный email**, который вы
   создали на шаге 3, и нажмите **«Опубликовать»**.

---

## 2. Cloudinary — хранение фото решений (бесплатно, без карты)

1. Зайдите на **cloudinary.com** → **Sign up free**.
2. На главной странице консоли (Dashboard) скопируйте **Cloud name**
   (например `dabc12xyz`).
3. Слева откройте **Settings (шестерёнка) → Upload** → в разделе
   **Upload presets** нажмите **Add upload preset**.
   - **Signing Mode**: выберите **Unsigned**.
   - Можно оставить остальные настройки по умолчанию, сохранить.
   - Скопируйте имя пресета (например `ml_default` или то, что вы
     назвали сами).

---

## 3. Впишите настройки в `config.js`

Откройте `site/config.js` и замените значения-заглушки:

```js
window.FIREBASE_CONFIG = {
  apiKey: "...",            // из firebaseConfig (шаг 1.4)
  authDomain: "...",
  projectId: "...",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "...",
};
window.ADMIN_EMAIL = "вы@ваша-почта.ру";   // email, который создали в шаге 1.3
window.CLOUDINARY_CLOUD_NAME = "...";       // шаг 2.2
window.CLOUDINARY_UPLOAD_PRESET = "...";    // шаг 2.3
```

Как только `apiKey` перестанет начинаться с `YOUR_`, сайт автоматически
переключится с демо-режима на реальную базу данных.

## 4. Публикация на GitHub Pages

### Вариант А — без командной строки (проще всего)

1. Зайдите на **github.com**, создайте новый репозиторий (**New
   repository**), например `kolloquium1`. Сделайте его **Public**.
2. Откройте репозиторий → **Add file → Upload files** → перетащите
   **все файлы из папки `site/`** (включая `config.js` с уже
   вписанными вами ключами) → **Commit changes**.
3. Зайдите в **Settings → Pages**. В разделе **Build and deployment**
   выберите **Source: Deploy from a branch**, **Branch: main /
   (root)** → **Save**.
4. Через 1–2 минуты сайт появится по адресу вида
   `https://ваш-логин.github.io/kolloquium1/`.

### Вариант Б — через git

```bash
cd site
git init
git add .
git commit -m "Сайт отработки коллоквиума 1"
git branch -M main
git remote add origin https://github.com/ВАШ-ЛОГИН/kolloquium1.git
git push -u origin main
```

Затем так же включите GitHub Pages в **Settings → Pages**, как в
варианте А (шаг 3).

## 5. Проверка

- Откройте опубликованный адрес — должна открыться страница для
  студентов, жёлтого баннера демо-режима быть не должно.
- Пройдите весь путь тестовым «студентом» — ответьте правильно на
  задачу, загрузите любое фото.
- Откройте `.../admin.html`, войдите email+паролем преподавателя
  (шаг 1.3) — должна появиться ваша тестовая запись.

Ссылку на сайт дайте студентам, ссылку на `admin.html` держите при себе.

## Как это работает

- Студент вводит ФИО, группу и **логин** (его он придумывает сам —
  простой текст, без пароля), чтобы результаты попадали в таблицу под
  его именем.
- Затем отмечает по каждой из 6 задач коллоквиума: решена полностью /
  наполовину / не решена.
- Сайт случайно выбирает из банка (`bank.json`) 6 задач того же типа
  (если не решена) или 3 (если наполовину) и даёт решать их по одной.
- Ответ проверяется автоматически (сверка с точным эталоном). После
  верного ответа открывается загрузка фото письменного решения —
  необязательная, но по желанию студента.
- Все попытки, ответы и фото сохраняются в Firestore/Cloudinary и
  видны вам в `admin.html` в виде таблицы с фильтрами и экспортом в CSV.

## Банк задач

`bank.json` содержит 30 задач каждого из 6 типов коллоквиума (180
всего), сгенерированных и проверенных программой `gen_bank.py`
(тема 2 — таблица TU, тема 3 — кривая безразличия, тема 4 — изменение
цены, тема 5 — эластичность, тема 5 — равновесие спроса/предложения,
тема 6 — TP/AP/MP). Если понадобится больше вариантов или другой
диапазон чисел — отредактируйте `gen_bank.py` (параметр `N` вверху
файла) и запустите `python3 gen_bank.py`, затем замените `bank.json`
в папке `site/`.

## Ограничения и что можно улучшить

- Вход администратора защищён паролем Firebase Authentication — для
  учебного сервиса этого достаточно, но это не банковский уровень
  защиты.
- Cloudinary upload preset в режиме **Unsigned** технически позволяет
  загрузить файл с прямым URL пресета кому угодно, кто его узнает —
  приемлемо для учебной задачи; для более строгой защиты можно
  перейти на подписанную загрузку через небольшую serverless-функцию.
- Если два студента придумают одинаковый логин, их результаты будут
  сохраняться под одним и тем же "студентом" в таблице. Попросите
  студентов использовать уникальный логин (например, фамилия + номер
  группы).
